## Bug Description

`do-work` builds its prompt from the configured frame, new messages, the full authorized issue conversation, the full pull-request conversation, and unresolved review threads. The newest messages are also listed separately before the full history. A long Spec Kit discussion with a full spec, plan, and task list can therefore exceed the prompt limit even when the latest comment is short.

On 2026-11-02, the `harness-experiments` Dev Container was running Automata 0.13.0. A short new comment on PR #50 caused the selected #10 turn to fail before Claude was invoked: the composed prompt was 97 KiB, above the 96 KiB per-argument limit.

Related: issue #40 and merged PR #169 move `do-work` prompts to stdin to avoid the OS argument-size limit. This issue requests bounded conversation history as a separate safeguard. The 96 KiB argument cap is not Claude's context-window limit: OS argument size and model token capacity are different limits. Sending a prompt on stdin removes the argv limit, but a sufficiently long conversation can still exceed the model's context window.

## Steps to Reproduce

1. Use `do-work` on an issue with a linked pull request and a long discussion containing large artifacts.
2. Add a short authorized comment to the issue or pull request.
3. Run `automata do-work`.
4. The full issue and pull-request histories are composed into one prompt; the run can fail on a transport or context-size limit before an executor answers.

## Expected Behavior

Automata checks the composed prompt against the applicable transport and model-context budgets before invoking the executor. If it is over budget, Automata removes the oldest conversation messages first until the prompt fits. It keeps the configured frame and newest authorized trigger message. It adds a clear marker that older history was omitted.

## Proposed Fix

- Measure prompt size before execution. Use a model-aware token budget when available, and enforce any separate transport limit.
- If the prompt exceeds the budget, drop the oldest issue/PR conversation messages first. Keep the configured frame, the newest authorized message, and current issue/PR identifiers.
- Add an omission marker with the number or date range of messages removed.
- Keep message-watermark behavior consistent with the trimmed prompt, so the trigger is not lost and the same oversized history does not cause a retry loop.
- If the frame and required newest context alone exceed the budget, stop with an actionable diagnostic instead of launching an impossible run.
- Add tests with long historical messages and a short newest message. Assert that trimming retains the trigger and stays within the configured budget.

## Acceptance Criteria

- A prompt over budget is reduced by dropping the oldest conversation messages before execution.
- The latest authorized trigger message and configured instructions are preserved.
- The prompt reports that older messages were omitted.
- The run does not repeatedly select the same omitted history or silently mark an unprocessed trigger as answered.
- Tests cover both byte-based transport limits and model-context budgeting where token counts are available.
